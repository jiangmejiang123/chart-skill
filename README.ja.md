# chart-skill

**同じ質問、2つの答え。**

![同じ質問、2つの答え](examples/chat/compare-before-after.png)

同じ質問文、同じプリセット（標準モード）、同じワークスペース、**唯一の違いはこの一式が入っているかどうか**。

左：**25秒**、7つの番号付き段落、読者が自分で優先順位を付ける。
右：**28秒**、1枚のフローチャート、分岐・出口・次の一手がすべて図の上に。

**ほぼ同じ時間。**
違うのは速度ではない。その3秒のあいだAIが「この話をどう組み立てよう」と考えているのか、「この話は何を図にすべきか」と考えているのか、その差だ。
変わるのはAIにできることではなく、どの手段で語るを選ぶか。

これは「チャートライブラリ」ではない。**エージェントスキル**だ：AIアシスタントのスキルディレクトリに入れておくと、
図で説明できる事柄に出会ったとき、まず判断を一巡させ、いきなり3段落並べたりはしない。

---

## 何が変わるのか

文章は**線形**だ：読者は最後まで読まないと要点が分からず、しかも頭の中で構造を組み立て直さなければならない。
図は**並列**だ：構造、比率、流れ、前後関係が、一目で全部見える。

だから判断基準は「描けるかどうか」ではなく：

> **この情報は、もともと図の形をしていたのではないか？**

イエスなら、描いたほうが書くより半分の時間で済む。ノーなら、無理に1枚作っても無駄になるだけだ。
このスキルにはこの2つが明記されている：**描くべきときは必ず描く、描くべきでないときは描いてはいけない。**

## 入れると、回答はこう変わる

スキルが持ち込むのは「描く能力」ではなく**判断**だ。同じ質問でも、回答の形が変わる。

**以前**——読者が頭の中で優先順位を付けなければならなかった：

> このエラーには通常3つの原因があります。1つ目はポートが使用中……2つ目は設定ファイルのパスが間違っている……3つ目は依存関係が揃っておらず、どれが欠けると module not found が出る……3つのうち最も多いのは1つ目……

**現在**：

![API 500 の切り分け順序](examples/chat/1-flow.png)

分岐、出口、どこから調べるかがすべて図の上にある。

**以前**：要件1週間、API2週間、フロントエンド2週間、結合1週間、負荷試験1.5週間、だいたい6週間くらいでしょ。

**現在**：

### 構造：一息で読み上げる説明から1枚のマインドマップへ

**以前**：上は接続層でゲートウェイのレート制限と認証、真ん中は業務層で注文・決済・通知、下はデータ層で主系DB・キャッシュ・キュー、あとは運用まわりの一式もある。

---

だが本当に難しいのはここではない。**いつ描くべきでないかを知ること**だ。

3つ以内の数値なら表で、2文で言えるなら直接言う、1回の回答で図は最大1〜2枚。
これはハードルールとして書かれている。`SKILL.md` の「三つの問い」と「描いてはいけないとき」の2節に——
「推奨」ではなく、回答のたびに必ず通すゲートとして。

## インストール

**3ステップ。3つ目はみんなが飛ばすが、飛ばすと何も起きない。**

**1. クローンして Python の依存を入れる**

```bash
git clone https://github.com/jiangmejiang123/chart-skill
pip install -r chart-skill/requirements.txt
```

**2. ディレクトリごとエージェントのスキルディレクトリに置く**

```
Claude Code  → ~/.claude/skills/chart-skill/
その他の agent → それぞれの skills ディレクトリ（例：~/.dsh/skills/、プロジェクト内の .agents/skills/）
```

**3. ワークスペースのルール（AGENTS.md）に一文を足す**

これがないと、スキルは「図を描いて」と言われるまで黙って待つだけだ。
スニペットは下の「[何に依存しているか](#何に依存しているか使う前にこの節を読む)」の節にある。4つの短い段落で、そのままコピーできる。

そのあと新しいセッションを開き、構造を説明すべき事柄を聞いて、表現の仕方が変わったか見てみよう。

> 忘れても大丈夫。スキルは初回に自分でワークスペースのルールを読み、
> 足りなければそう伝えてスニペットを渡す。覚えておく必要はない。

> これが見るのは `SKILL.md`（モデルに渡す判断ルール）＋ `scripts/`（実行スクリプト）だ。
> `SKILL.md` がなければ単なる描画ツールになり、スクリプトがなければ単なる提案になる——両方必要だ。

## 何に依存しているか（使う前にこの節を読む）

このスキルは**2つの半分**でできていて、片方が欠けると効かない：

| 層 | 置き場所 | 役割 |
|---|---|---|
| スキル本体 | `SKILL.md` + `scripts/` | どの図を描くか、どう描くか、データ形式 |
| **行動制約** | **あなたのワークスペースのルール（AGENTS.md など）** | **「描けるなら段落を書くな」というハード要件** |

2つ目の半分を省けない理由：スキルはトリガー語で読み込まれる仕組みであり、「この部分は図にすべきか」は**毎ターン行う判断**だからだ。
スキルだけあってルールがなければ、AIは「図を描いて」と言われるまで静かに待つ。ルールがあって初めて、自分から描く。

### この段落を AGENTS.md に足すことを勧める

```markdown
## C4 · 先に図、後で文字

一言で言えるなら一言で。比較・箇条書き・パラメータは表に。フロー・構造・トレンドはそのまま図に。
文章は結論と要点の説明だけ、通常8行以内。

**違反形態**（出たら必ず図を描き、文字で代替してはならない）：
① 番号付きの段落が3つ以上あり、かつ互いに前後関係または依存関係がある；
② 「もし……なら……」という分岐記述を含む（トラブルシュートの順序、決定木、条件分岐フロー）；
③ 「どちらが先か」「どこで詰まるか」「何から構成されるか」を文字で列挙している。

番号付きリストは「箇条書き」ではない。順序を持つ番号付きリストは、まさにフローチャートにすべきものだ。

**例外**：ユーザーがそのまま打つコマンド、そのままクリックするメニューパスは、番号付きリストが正しい。
判断基準は「この行を単独で取り出して、そのまま実行できるか」。

**描いたら止める**：図から読み取れることを本文で繰り返さない。
```

### 実測：どの harness なら効くか

| Harness | 結果 | 理由 |
|---|---|---|
| DSH 標準プリセット | ✅ 最初の質問で図が出る | 毎ターン、ワークスペースのルール全文をコンテキストに注入 |
| ZCode | ✅ 同上 | 同上 |
| ミニマル起動系プリセット<br>（まず2段階の導入を走らせ、昇格後は「ルールのファイル名」だけを提示するもの） | ❌ 最後まで純粋なテキスト | ルール全文が一度も注入されず、スキル一覧も遅延される |

![実際のセッション：1回の質問で、そのまま図が出る](examples/chat/real-session-zcode.png)

**結論：このスキルは、あなたの harness がワークスペースのルールを読むことを前提としている。読まないタイプなら、自力で描くのを待たずに——モードを変えるか、「図を描いて」と直接言うこと。**

### トリガー語はかなり広く取ってある

説明には「図を描いて / フローチャート / マインドマップ」のような明示的な言い方だけでなく、実際の場面の言い回しも入れてある：

> どう切り分ける / 切り分けの順序 / まず何をする / ステップごとに / 流れは何か / どう選ぶ / どの案が /
> 何が違う / 何から構成される / 構造は何か / アーキテクチャ / いつリリースできる / スケジュール / 構成比 / トレンド / 推移

ユーザーは聞きたいとき、たいてい「フローチャートを描いて」とは言わず、「サービスが落ちたらどう調べる」と言う。
**トリガー語を狭く書くと、スキルは出番の瞬間を永遠に待つことになる。**

最終的にどのホストが、どんなタイミングでスキル一覧をモデルに渡すのか——それは harness の設計上の選択であり、スキルが決められることではない。

## 自分で動かしてみる

インストールしなくてもコマンドラインツールとして使える：

```bash
python scripts/viz.py --demo out          # 12枚をまとめて出力
python scripts/viz.py bar --data '{"周一":12,"周二":19,"周三":15}' --title "每周提交" --out a.png
```

## 12種類の図

![12種類の図の一覧](examples/overview.png)

| コマンド | 何を描くか | データ形式 |
|---|---|---|
| `bar` | 棒グラフ / 横棒の比較 | `{"A":12,"B":19}` |
| `line` | 折れ線、複数系列 | `{"系列1":[1,2,3],"系列2":[3,2,1]}` |
| `pie` | 構成比 | `{"开发":38,"会议":16}` |
| `scatter` | 2つの量の関係 | `{"x":[...],"y":[...]}` |
| `heatmap` | 行列ヒートマップ | `{"matrix":[[..]],"rows":[..],"cols":[..]}` |
| `flow` | フローチャート / 判断分岐 | `{"nodes":[{"id":"a","label":"开始"}],"edges":[["a","b"]]}` |
| `mind` | マインドマップ / 階層分解 | `{"root":"主题","children":{"分支":["叶子"]}}` |
| `gantt` | ガントチャート / スケジュール | `{"unit":"小时","tasks":[{"name":"改造","start":0,"dur":1.2}]}` |
| `sankey` | 流れ / コンバージョンファネル | `{"left":[["搜索",40]],"right":[["安装",38]],"flows":[["搜索","安装",16]]}` |
| `treemap` | 構成比（要素が多いときほど省スペース） | `{"代码":45,"文档":22}` |
| `network` | 関係ネットワーク / 依存関係 | `{"edges":[["A","B"]]}` |
| `formula` | LaTeX 数式 | `--expr "E=mc^2"`、複数は `;;` 区切り |

全部の見た目は `examples/` にある——すべて `--demo` の出力そのままで、後加工はしていない。

## CLI

```
python scripts/viz.py <kind> [options]

  --data JSON        インラインの JSON、または - で stdin から読む
  --json-file PATH   データファイル
  --expr LaTeX       formula のみ；複数は ;; 区切り
  --title TEXT       図のタイトル
  --out PATH         画像を出力（必須。--demo を使う場合を除く）
  --width / --height インチ
  --dpi N            デフォルトは 150
  --demo DIR         12枚のサンプル図を一括生成
```

## 依存関係

Python パッケージは `requirements.txt` を参照：`matplotlib` `seaborn` `networkx` `squarify` `graphviz`。

このうち `flow` と `mind` はさらに **Graphviz のシステムバイナリ**が必要（Python の `graphviz` パッケージはそれを呼び出すだけの殻）：

| システム | インストール |
|---|---|
| Windows | `winget install graphviz` または [graphviz.org/download](https://graphviz.org/download/) |
| macOS | `brew install graphviz` |
| Debian / Ubuntu | `apt install graphviz` |

インストール後のターミナル再起動は不要——スクリプトは `PATH` のほかに、いくつかの一般的なディレクトリも見て `dot` を探す。

## 中国語フォント

プラットフォームごとに自動検出：**Microsoft YaHei → PingFang → Noto Sans CJK → 源ノ角ゴシック → WenQuanYi → SimHei**。
どれも無い場合は stderr に警告が出て、中国語は豆腐（□）で表示される。1つ入れれば解決：

```bash
apt install fonts-noto-cjk            # Debian / Ubuntu
brew install font-noto-sans-cjk-sc    # macOS
```

配色とフォントは `scripts/vizlib.py` の先頭にあり、定数を書き換えるだけでよい。系列が7つを超えると色は自動で循環する。

## 適用範囲

- **構造・比率・流れ**だけを扱う。写真のような質感のイラスト、カバー用ポスター → 画像生成モデルを使う
- 動画・アニメーション → ffmpeg 系ツール；3D → 3D ツール；ドキュメント/PPT/Excel → office 系ツール
- インタラクション（絞り込み、クリック）だけが欲しい → HTML を書く。静的な図は描かない
